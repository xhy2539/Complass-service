# 合规罗盘 v0.2 对 Coze 工作流的影响说明

## 概述

v0.2 版本在后端增加了三个核心能力：规则库数据库化、合同文本脱敏、合同优化版本生成。其中**规则库**和**脱敏**会直接影响 Coze 工作流的输入输出，工作流需要同步调整以充分利用这些能力。

---

## 一、所有工作流通用变更：脱敏文本

### 变化

v0.2 在调用 Coze 之前对合同文本做了深度脱敏，敏感信息被替换为占位符：

| 原始内容 | 替换为 | 示例 |
|---|---|---|
| 公司名称 | `公司A`、`公司B`... | 深圳市示例科技有限公司 → 公司A |
| 统一社会信用代码 | `统一社会信用代码A`... | 91110108MA... → 统一社会信用代码A |
| 身份证号 | `身份证A`... | 110101199001011234 → 身份证A |
| 手机号 | `电话A`... | 13800138000 → 电话A |
| 固话 | `电话A`... | 0755-12345678 → 电话A |
| 邮箱 | `邮箱A`... | contact@example.com → 邮箱A |
| 银行账号 | `银行账号A`... | 6222021234567890 → 银行账号A |
| 开户行 | `开户行A`... | 开户行：中国工商银行深圳分行 → 开户行A |
| 地址 | `地址A`... | 地址：深圳市南山区科技园 → 地址A |
| 人员姓名 | `人员A`... | 联系人：张三 → 联系人：人员A |

**金额和日期保留原文，不做替换。**

### 工作流需要做什么

在 prompt 中加入以下说明，避免工作流误判：

```
【脱敏说明】
合同文本中以下占位符为脱敏处理后的结果，不代表合同信息缺失：
  - 公司A/公司B/... ：公司名称占位符
  - 统一社会信用代码A/... ：统一社会信用代码占位符
  - 身份证A/... ：身份证号占位符
  - 电话A/电话B/... ：电话号码占位符
  - 邮箱A/邮箱B/... ：邮箱占位符
  - 银行账号A/... ：银行账号占位符
  - 开户行A/... ：开户行银行占位符
  - 地址A/地址B/... ：地址占位符
  - 人员A/人员B/... ：人员姓名占位符
金额和日期为原文未修改。
请勿因上述占位符而判定合同主体信息缺失、联系方式缺失或条款不完整。
```

### 影响范围

- 审查工作流的 `sanitized_text` 字段
- 比对工作流的 `old_text` / `new_text` / `diff_texts` 字段

## 二、审查工作流（review_workflow）

### 2.1 输入新增字段

完整的 `input` JSON 字符串：

```json
{
  "file_id": "上传到Coze的文件ID",
  "contract_type": "通用",
  "rule_version_id": "uuid-xxx",
  "rules": [
    {
      "rule_code": "COM-FIN-001",
      "contract_type": "通用",
      "review_module": "财务",
      "risk_name": "合同金额不明确",
      "check_point": "是否明确合同总金额、币种、大小写金额",
      "trigger_condition": "合同仅写费用另行协商或按实际结算或未写明总金额",
      "default_risk_level": "高",
      "suggestion_template": "建议明确合同总金额、币种、大小写金额及费用构成",
      "example_clause": "合同费用由双方另行确认。"
    }
  ],
  "sanitized_text": "脱敏后的合同全文（新）",
  "sanitization_enabled": true
}
```

与 v0.1 的区别：

| 字段 | v0.1 | v0.2 |
|---|---|---|
| `rules` | `[]`（空数组） | 包含完整规则对象的数组 |
| `sanitized_text` | 不存在 | 新增，脱敏后的合同全文 |
| `sanitization_enabled` | 不存在 | 新增，布尔标记 |

### 2.2 输出新增字段

每个风险点需在原有字段基础上新增 `rule_code`：

```json
{
  "key": "合同金额不明确",
  "risk": "高",
  "tip": "合同仅写费用另行协商，未明确总金额",
  "advice": "建议在合同第二条明确约定合同总金额为人民币XX元（大写：XXX元整）",
  "content": "合同费用由双方另行协商确定。",
  "replace_text": "合同总金额为人民币XXX元（大写：XXX元整），费用构成详见附件一。",
  "rule_code": "COM-FIN-001"
}
```

`rule_code` 必须与输入 `rules` 中某条规则的 `rule_code` 一致，后端用此字段关联规则详情和默认风险等级。

### 2.3 工作流 prompt 需增加

```
【规则驱动审查】
请按 rules 数组中的每条规则逐项审查合同文本：
  - rule_code：规则编号，命中时必须在输出中携带此字段
  - risk_name：风险名称
  - check_point：检查要点，决定审查什么
  - trigger_condition：触发条件，决定何时命中
  - default_risk_level：默认风险等级（高/中/低），作为风险定级的参考
  - suggestion_template：修改建议模板，可据此生成具体的修改建议
  - example_clause：示例问题条款，帮助理解风险场景

输出要求：
1. 每个命中规则的风险点必须包含 rule_code 字段，值为对应规则的 rule_code
2. 按风险等级排序输出（高风险在前）
3. 通过审核的项不需要输出
```

## 三、比对工作流（comparison_workflow）

### 3.1 输入变化

完整入参：

```json
{
  "task_type": "contract_comparison",
  "old_text": "脱敏后的旧合同全文",
  "new_text": "脱敏后的新合同全文",
  "diff_stats": { "total": 15, "added": 5, "deleted": 3, "modified": 7 },
  "diff_texts": [
    {
      "type": "modified",
      "content": "修改内容：公司A应向公司B支付人民币100,000元。 → 公司A应向公司B支付人民币150,000元。"
    }
  ],
  "contract_type": "通用",
  "rule_version_id": "uuid-xxx",
  "rules": [
    {
      "rule_code": "COM-FIN-001",
      "review_module": "财务",
      "risk_name": "合同金额不明确",
      "check_point": "是否明确合同总金额、币种、大小写金额",
      "trigger_condition": "合同仅写费用另行协商或按实际结算或未写明总金额",
      "default_risk_level": "高",
      "suggestion_template": "建议明确合同总金额、币种、大小写金额及费用构成",
      "example_clause": "合同费用由双方另行确认。"
    }
  ]
}
```

与 v0.1 的区别：

| 字段 | v0.1 | v0.2 |
|---|---|---|
| `old_text` / `new_text` | 原文 | 脱敏后的文本 |
| `diff_texts[].content` | 原文 | 脱敏后的文本 |
| `rules` | `[]`（空数组） | 包含完整规则对象的数组 |

### 3.2 输出新增字段

每个 diff item 需包含 `rule_id`：

```json
{
  "type": "modified",
  "risk_level": "中",
  "old": "公司A应向公司B支付人民币100,000元。",
  "new": "公司A应向公司B支付人民币150,000元。",
  "analysis": "付款金额从100,000元变更为150,000元，需确认变更依据",
  "advice": "建议在合同中注明金额变更的原因和审批依据",
  "rule_id": "COM-FIN-001"
}
```

### 3.3 工作流 prompt 需增加

同审查工作流的【脱敏说明】和【规则驱动审查】部分。

**注意**：比对工作流中 `old_text` / `new_text` / `diff_texts` 均已脱敏，且 diff_texts 中的差异内容与 diff_stats 中的统计数字对应，请基于 diff_texts 中的具体差异并结合 rules 进行语义分析。

## 四、兼容性说明

如果 Coze 工作流暂不更新：

| 缺失项 | 后果 | 严重程度 |
|---|---|---|
| 未处理脱敏占位符 | 可能误报"主体信息缺失"、"联系方式缺失"等 | 中 |
| 未使用 rules 驱动审查 | 规则库无法指导审查，审查结果可能偏离规则定义 | 高 |
| 输出未包含 `rule_code`/`rule_id` | 风险点无法关联规则详情，前端无法展示规则来源 | 中 |
| 其他字段不变 | 不影响 | 无 |

**不会导致**：接口报错、任务失败、数据丢失。所有新增字段后端都有默认值兜底。
