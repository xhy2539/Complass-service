# 合规罗盘 (Complass) 用户使用手册

## 1. 系统概述

合规罗盘是一套 AI 辅助的合同审查工作台，帮助法律/采购人员高效审查合同、发现风险、
从历史修改中提炼审核规则。

**三大核心功能：**

| 功能 | 适用场景 |
| ------ | -------- |
| 合同审查 | 上传一份合同，AI 分析风险点 |
| 版本比对 | 对比修改前后两个版本，识别差异和风险 |
| 规则逆向 | 根据合同修改行为，反向提炼可复用的审核规则 |

---

## 2. 系统架构

```
用户浏览器 (React)
        │
        ▼
  Nginx (port 80)
        │ /api/* 代理
        ▼
  FastAPI 后端 (port 8080)
   ├── MySQL (合同/任务/规则/用户数据)
   ├── Redis (会话缓存)
   ├── Coze (合同审查/比对 AI)
   ├── MiniMax M3 (规则逆向解析 LLM)
   └── RAG 服务 (port 8000)
        ├── bge-base-zh 语义检索
        ├── FAISS 向量索引
        └── SQLite 知识库
```

## 3. 部署配置

### 3.1 环境要求

- Docker 24+ & Docker Compose
- 4GB+ 内存（含 RAG 服务）
- 20GB+ 磁盘

### 3.2 启动服务

```bash
cd /opt/complass-service
cp .env.example .env
# 编辑 .env 填入 COZE_ACCESS_TOKEN / MINIMAX_API_KEY 等

docker compose up -d

# 首次部署时构建 RAG 索引
sleep 30  # 等 RAG 容器启动
curl -X POST http://localhost:8000/rebuild
```

验证各服务：

```bash
curl http://localhost:8080/health   # 后端
curl http://localhost:8000/health   # RAG
curl http://localhost:80/           # 前端
```

### 3.3 环境变量

| 变量 | 必填 | 说明 |
| ------ | ------ | ------ |
| `DATABASE_URL` | 是 | MySQL 连接串 |
| `COZE_ACCESS_TOKEN` | 是 | Coze API 访问令牌 |
| `MINIMAX_API_KEY` | 是 | MiniMax API 密钥（规则逆向用） |
| `JWT_SECRET_KEY` | 是 | JWT 签名密钥 |
| `REDIS_HOST` | 否 | Redis 地址，默认 `redis` |
| `LLM_PROVIDER` | 否 | LLM 提供商，默认 `minimax` |
| `RAG_SERVICE_URL` | 否 | RAG 服务地址，默认 `http://rag-service:8000` |

## 4. 用户操作指南

### 4.1 注册与登录

访问 `http://82.156.132.43/login`：

- **注册**：填写邮箱、手机号、昵称、密码（6位以上）
- **登录**：使用邮箱或手机号 + 密码
- 登录后获得 7 天有效的 JWT Token

### 4.2 合同审查

**操作步骤：**

1. 进入首页，点击"新建审查"
2. 上传合同文件（支持 `.docx` / `.pdf` / `.txt`）
3. 选择合同类型（采购合同/服务合同/通用等）
4. 等待 AI 分析（通常 30-120 秒）
5. 查看风险点列表，每个风险点包含：
   - 风险等级（高/中/低）
   - 风险描述和原文证据
   - AI 修改建议
6. 对每个风险点进行确认/忽略，填写复核备注

**安全说明：** 合同中公司名、电话、邮箱、身份证等敏感信息在送 AI 分析前已自动脱敏，结果返回前恢复。

**导出功能：** 点击"导出"可将修改后的合同文本保存为 DOCX，保留原始文档的全部格式
（字体、表格、加粗、页眉页脚等）。

### 4.3 合同版本比对

**操作步骤：**

1. 进入"合同比对"页面
2. 分别上传旧版和新版合同文件
3. 选择合同类型
4. 等待比对完成
5. 查看差异明细：
   - 新增内容（绿色标记）
   - 删除内容（红色标记）
   - 修改内容（蓝色标记）
6. 查看 AI 增强的风险分析

### 4.4 规则逆向解析（核心特色）

这是合规罗盘的独特功能：**从合同的修改行为中，反向提取可复用的审核规则。**

**操作步骤：**

1. 进入"规则库" → "逆向解析任务" → "新建解析"
2. 上传 1-5 组修改前后的合同文件
3. 填写：
   - 任务名称
   - 合同类型（如"采购合同"）
   - 审核视角（甲方/乙方/通用）
4. 提交后等待解析完成
   - 状态流转：`parsing` → `pending_confirm`（待确认）→ `completed`（已入库）
5. 点击任务进入候选规则确认页
6. 逐条审核候选规则，标记为"纳入"或"忽略"
7. 点击"确认入库"将纳入的规则写入正式规则库

**每条候选规则包含：**
- 风险名称、检查点、触发条件
- 修改前后证据（来源追踪）
- 置信度评分
- 审核模块分类

**说明：** 即使未配置 LLM 凭证，系统仍可通过知识库降级（stub）生成候选规则。
此时置信度较低，建议人工复核后入库。

### 4.5 规则库管理

- **查看规则**：进入"规则库"页面，支持按合同类型/模块/状态筛选
- **CSV 导入**：批量导入审核规则（含合同类型、模块、风险名、检查点等字段）
- **规则维护**：启用/禁用、编辑、删除
- **规则编号**：入库自动生成 `REV-FIN-xxxxxxxx` / `REV-LAW-xxxxxxxx` 等编号

### 4.6 任务管理

所有任务在"历史记录"页面集中管理：

- 按类型（审查/比对）筛选
- 按状态（待处理/处理中/已完成/失败）筛选
- 查看任务详情、风险结果
- 删除已完成的任务

## 5. RAG 语义检索服务

合规罗盘内置了独立的知识库检索服务，用于为规则逆向提供语义增强的案例匹配。

**检索流程：**

```
查询文本 → bge-base-zh 语义向量 → FAISS 向量搜索
         → BM25 关键词兜底 → 加权融合
         → MiniMax M3 重排序 → 返回 Top-3 匹配案例
```

**降级保障：**

| 层级 | 说明 | 触发条件 |
| ------ | ------ | -------- |
| RAG 服务 | 语义检索（精度最高） | 服务可用 |
| 本地检索 | MD5 hash + JSON 扫描 | RAG 超时/不可用 |
| 硬编码兜底 | 预设付款/违约模板 | 前两层均失败 |

RAG 服务不可用时，系统自动降级，不影响主流程正常运行。

## 6. CI/CD 流水线

每次代码提交推送到 Gerrit 后自动触发：

| 阶段 | 检查内容 |
| ------ | -------- |
| Lint | ruff 代码风格 + import 顺序 |
| Format | ruff 格式化一致性 |
| Type Check | mypy 静态类型检查 |
| Test | pytest 28 个自动化用例 |
| Syntax | Python 编译检查 |
| Import | 主应用导入验证 |

合并到 dev 分支后自动部署到生产服务器（`docker compose up -d --build`）。

## 7. 常见问题

**Q: 审查为什么不返回风险点？**
A: 确认 Coze workflow ID 正确，合同文本非空，`use_coze=true` 已传。

**Q: 逆向规则生成 0 条候选？**
A: 先确认 MiniMax API 可用，其次系统会降级到知识库 stub。
检查 `contract_type` 和 `review_role` 是否填写。

**Q: RAG 服务启动失败？**
A: 首次启动需下载 bge-base-zh 模型（~300MB），使用 HuggingFace 镜像。
若网络不通，服务会降级到本地检索。

**Q: 部署后前端 502？**
A: 检查磁盘空间（`df -h`），Docker 日志（`docker compose logs`），
确保 MySQL 先于后端启动（已配置 `depends_on`）。

**Q: 如何查看检索日志？**
A: `docker logs complass-rag` 查看 RAG 服务日志，
`docker logs complass-service | grep RAG` 查看后端检索调用。
